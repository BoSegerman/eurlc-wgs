
EURLC-WGS -- whole genome sequencing analysis for Campylobacter, Salmonella,
E. coli and Listeria (Illumina reads or assemblies)

USAGE
    eurlc-wgs [datadir=<folder>] [options]

    Without datadir= the current folder is analysed. Results go to
    <data folder>/eurlc-wgs, or to exactly the folder given with outdir=.
    Arguments are name=value or --flag; a path may also follow the name
    (datadir /data/run192). An argument may be given only once.

INPUT AND OUTPUT
    datadir=<folder>             Folder with FASTQ (paired or single) and/or
                                 FASTA files
    outdir=<folder>              Write results to exactly this folder
    database=<folder>            Database folder (default ~/eurlc-wgs_db)
    configfile=<file>            Settings file (default <database>/eurlc-wgs.config)
        configfile=write         write the current settings to a file and exit
        configfile=default       ignore any settings file
    --recursive                  Also look for input files in subfolders
    --fastq / --fasta            Analyse only FASTQ / only FASTA input

    Illumina names lose their sample number and lane in the sample name
    (PT43_S12_L001_R1_001.fastq.gz -> PT43); one sample on several lanes is
    merged before the analysis.

AN EXISTING OUTPUT FOLDER
    (asked by default)           overwrite, resume or stop
    --resume                     Continue: reuse finished results, run what is
                                 missing or failed
    overwrite=yes | no           Overwrite without asking / stop
                                 (--overwrite = overwrite=yes)
    rerun=<step>[,<step>...]     In an existing folder (implies --resume): run
                                 these steps again, and every step that depends
                                 on them
    summarize                    Re-evaluate QC with the current thresholds,
                                 validate and verify again, and rebuild the
                                 report and data/rundata.json (no tools are
                                 run)

WHAT IS ANALYSED
    enable=<tool|species>[,...]  Switch tools on, e.g. enable=sistr or
                                 enable=Salmonella (all its typing tools)
    disable=<tool|species>[,...] Switch tools off, e.g. disable=bakta
    species_scope=<list>         Species the typing tools are prepared for
    <section>.<param>=<value>    Any single setting, e.g.
                                 fastp.arguments="--length_required 50"
                                 spades.timeout=4h
    <param>=<value>              A [general] setting, e.g. threads=8

    --qc-screen                  Quick check of the raw reads only (Q30
                                 coverage, species, other genus, read length);
                                 traffic-light report in eurlc-wgs_qcscreen/

RUNNING
    threads=<n>                  Threads per tool
    parallel_mode=on             Run several samples/steps at once within
                                 max_threads=<n> / max_ram_gb=<n>
                                 (default: what the computer has)
    --assume-yes                 Answer installation questions with yes
                                 (never: overwriting results or a config file)
    --verbose                    More detail in the log
    --no-color / --color         Coloured screen output off / on

    While running: write pause, resume or terminate to
    <output>/control/cmd to pause, continue or stop the run.

CHECKING THE RESULTS
    validate=auto|off|<folder>   Compare with an EURL validation dataset
                                 (auto: a *_validation_profile.yml in the data
                                 folder or the folder above); report/validation/
    verify_reference=auto|off|<file or folder>
                                 Compare with the results fingerprint of an
                                 earlier run (auto: the newest in reference/
                                 next to the data); report/verification/
    verify_expect=<area>[,...]   Differences that are expected, e.g.
                                 verify_expect=amr,qc.coverage
    validated_species=<species>[, ...]
                                 The species this configuration is validated
                                 for, e.g. "Campylobacter jejuni, Campylobacter
                                 coli" (set it in the configuration file, so
                                 that the seal covers it). Samples of other
                                 species (or without a species call) are
                                 analysed, but marked and not reportable

INSTALLATION AND MAINTENANCE
    --setup [--optional]         Install tool environments and databases
                                 (--optional: also the tools that are off)
    installtool=<tool>           Install one tool's environment
    reinstalltool=<tool>         Remove and install again
    removetool=<tool>            Remove one tool's environment
    infotool=<tool>              Show a tool's settings and installation
    --freeze-databases[=<db>,..] Copy databases to frozen, versioned folders
    --verify-databases           Check every database in full and name its
                                 version
    --generate-seal[=<name>]     Seal the configuration (settings, frozen
                                 databases, tool environments, pipeline
                                 version). Also writes the exact package
                                 list of every environment to
                                 <database>/conda_envs/; with those lists
                                 in the database folder, install.sh and
                                 --setup make the same environments on
                                 another computer
    --installation-check[=<set>[,<set>]]
                                 Check this installation: run the check set(s)
                                 in <database>/installation_check/ and compare
                                 with their expected results and reference run
                                 (docs/installation-check.md). Exit code 0 when
                                 every set passes, 1 otherwise
    --remap-check [--convert] <output folder>
                                 Check remap results from an earlier version
                                 against the current method (--convert: take
                                 over the identical ones, so the step is not
                                 run again)

cgMLST SCHEMAS
    --list-schemas               Installed and available schemas
    --install-schema=<name>      Install a schema from the catalog
    --install-efsa-schemas[=<species>,...]
                                 Install the EFSA schemas and filters
                                 (campylobacter, ecoli, salmonella, listeria)
    --import-schema=<folder>     Install a schema you already have

INFORMATION
    --help                       This text
    --version                    The pipeline version
    --versions                   The pipeline and every tool's version

EXIT CODES
    0 finished   1 error   2 nothing to analyse   3 finished, a sample was
    abandoned   4 interrupted   5 finished, a step failed or timed out
    6 stopped with terminate

FILES IN THE OUTPUT FOLDER
    report/main_report.html      The report
    report/tables/               Result tables, and the results fingerprint
                                 (eurlc_results_fingerprint.json.gz)
    data/rundata.json            All results of the run, for scripts
    log/log.txt                  Full log (search "EURLC-WGS RUN")
    log/run_summary.txt          Summary of the last run
    log/run_status.json          Status for scripts and GUIs
    log/events.jsonl             One line per step started/finished

COMPANION TOOLS (installed with the pipeline; --help on each)
    eurlc-wgs-inspect            Look into output folders: inventory, extract a
                                 small package, summarize many runs, compare
                                 runs (repeatability, after an update)
    eurlc-validate               Compare any pipeline's results with an EURL
                                 validation dataset
    eurlc-cgmlst-compare         Why two cgMLST results of the same isolate
                                 differ (profiles, schemas)

EXAMPLES
    eurlc-wgs datadir=/data/run192 threads=8
    eurlc-wgs datadir=/data/run192 outdir=/analysis/run192 --resume
    eurlc-wgs datadir=/data/run192 --qc-screen
    eurlc-wgs outdir=/analysis/run192 rerun=sistr enable=sistr
    eurlc-wgs outdir=/analysis/run192 summarize
    eurlc-wgs-inspect compare run1/eurlc-wgs run2/eurlc-wgs --out repeatability/

Full documentation: docs/eurlc-wgs-user-manual.md in the source
repository (https://github.com/BoSegerman/eurlc-wgs).
